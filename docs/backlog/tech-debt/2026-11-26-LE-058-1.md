# LE-058: the session review re-reads the whole journal for its mistakes

Found while doing LE-058. `app.review.SessionMistakes` calls `TradingMistakes.find(journal.readAll(), …)` on every
`GET /session-review`; with the file journal that parses every line of the file per request, and it runs outside the
sequencer, so the review and the mistakes may see a batch apart.

Suggested fix: keep the events `TradingMistakes` needs in a read model in `application` (like
`SessionReviewProjection`) and answer both from one `sequencer.call`. Also: no book snapshots are kept, so B4 (wide
spread) never reaches the API — the same read model could sample the top of the book. Not done in LE-058: both need
`backend/application`, outside the task's paths.
