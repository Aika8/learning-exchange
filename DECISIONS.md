# Decisions — increment 1 (order book)

Choices the brief left open. Each one is the simplest behaviour; revisit any of them deliberately.

- Engine ownership: per the intent, the agent writes `engine` and its tests; Aika reviews this file and tests behaviour via the REPL.
- Java version: the brief said 17, the intent said 25; Aika chose 25 (Gradle toolchain).
- Obsolete spec: `intent/01-order-book.spec.md` was already deleted in commit 38363bd; nothing to delete.
- Price and quantity are `long` integer ticks/units; no decimals, no tick size.
- Zero or negative quantity: rejected with `IllegalArgumentException` by `Order.limit` / `Order.market`.
- Zero or negative limit price: rejected with `IllegalArgumentException`.
- Market order has no price: `Order.market(side, qty)` takes none and `Order.Market` exposes none.
- `Order` is a sealed interface; the factories return the concrete records `Order.Limit` / `Order.Market`.
- No price bands or collars: a market order walks the whole opposite side.
- Self-trade: deferred until accounts/owners exist (increment 2).
- Time priority is arrival order into the level's deque; the caller-supplied `timestamp` was dropped with the old constructor, and the engine id reflects arrival order.
- Order ids are generated by `OrderBook` from a monotonic `long` counter starting at 1, per book instance; never reused, including after full fill or cancel.
- Every submitted order gets an id, including market orders and orders that fill completely and never rest.
- Id counter overflow is not handled.
- `submit` takes an `Order` (immutable parameters from the factories); submitting the same `Order` value twice creates two independent orders with two ids.
- `submit` returns `SubmitResult(orderId, trades)` with a derived `filledQty()`; it does not expose rested or cancelled quantity separately.
- The unfilled market remainder is computed by the caller as `order.qty() − result.filledQty()`.
- `Order` is immutable; remaining quantity of resting orders is tracked inside the book.
- `Trade` records buy order id, sell order id, price, qty and `aggressorSide` (the side of the incoming order, for limit and market orders alike).
- `cancel` returns false for unknown, already filled, or already cancelled ids.
- `cancel` removes from the level's deque in O(n) of that level; acceptable at learning scale.
- Read-only `bids(depth)` / `asks(depth)` returning aggregated `Level(price, qty, orders)` were added so the REPL can print the top 5 levels.
- Repl lives in package `repl`, outside `engine`.
- Repl prints the id assigned by the book after each submit; an order rejected by the factories never reaches the book and consumes no id.
- Repl: `book` prints only the book; unknown or malformed commands print an error and the book is not reprinted; end of input acts like `quit`.
- Repl prints asks highest-first above the spread and bids highest-first below it.

# Decisions — M0 (repo reshape)

- Java 25 toolchain: Gradle uses an installed JDK 25 (sdkman here); `foojay-resolver-convention` 1.0.0 in `settings.gradle` downloads one when none is installed.
- One Gradle build at the repo root (wrapper stays at the root); backend modules are `:backend:engine` and `:backend:repl`. Further ADR-0009 modules are added when their milestone needs them.
- The REPL is its own module `backend/repl` depending on `engine`, so `engine` stays dependency-free. It is a dev tool, not one of the ADR-0009 deployables; it can be dropped once `make dev` starts the real backend.
- `make dev` runs the REPL until the backend exists (M1).
- Invariant №3 (never crossed) and №2 (limit respected) are tested by examples plus a seeded random flow (5 000 operations, seed 42) that checks both after every step.
